Privacy Policy

SquareMap thing

Last updated: October 29, 2026

1. Scope

This policy describes the data handled by SquareMap thing (the “Activity”), an independently operated Minecraft world-map viewer launched inside Discord. It covers the Activity's authentication gateway and embedded squaremap viewer, not Discord's own platform or other applications and bots used in the Minecraft server.

2. Information the Activity processes

  • Discord account information: After you authorize the Activity, it receives your Discord user ID and username or display name to identify your session. It also checks the list of Discord servers available through the granted guilds OAuth scope to confirm membership in the designated server.
  • Authorization information: The Activity briefly exchanges a Discord OAuth authorization code for an access token, which it uses to verify identity and server membership and to authenticate the Discord embedded application.
  • Session information: The Activity creates a random session identifier stored in a secure, HTTP-only, partitioned browser cookie. Its backend temporarily associates the identifier with your Discord user ID, display name, and expiration time.
  • Minecraft map information: The Activity shows rendered terrain, and may show Minecraft usernames, locations, and world/dimension information for players made visible by squaremap. Map visibility depends on the Minecraft server's squaremap configuration.
  • Technical requests: Loading the Activity sends ordinary network requests to its hosting and tunneling providers. Those providers may process connection metadata such as IP addresses and request timing according to their own policies.

3. Why this information is used

The Activity uses Discord account data solely to authorize access for members of the designated Discord server, maintain a temporary signed-in session, and display your name in the viewer. Minecraft map data is used to render the interactive map and player markers. The Activity does not use this information for advertising or sell it.

4. Storage and retention

The current Activity backend maintains authorization sessions in server memory, not in a persistent account database. Session records expire after eight hours by default, or sooner if the server process restarts. The browser cookie is configured for the same period. The current Activity code does not intentionally write a persistent history of individual map visits or player positions. Browser caches, the Minecraft/squaremap server, Discord, and hosting providers may retain other technical data independently.

5. Sharing and service providers

The Activity communicates with Discord for authentication and server-membership checks and with the Minecraft server's squaremap service to load map tiles and visible player information. Its public HTTPS connection is provided through the configured tunnel service (currently Tailscale Funnel, if used by the operator). The published legal pages are hosted through GitHub Pages, if that hosting option is used. Each external service processes information under its own terms and privacy practices. The Activity operator does not sell personal information.

6. Security and visibility

The backend restricts map access to authenticated Discord members of the designated server. It uses short-lived session cookies and a server-side gateway rather than exposing the Minecraft server's administration dashboard. However, no internet service can guarantee absolute security. Authorized users can still view, save, or share screenshots of any Minecraft locations visible to them.

7. Your choices and requests

You can stop using the Activity or revoke its access in your Discord account's authorized applications settings. If you leave the designated Discord server, new authorization checks will prevent a new session, although an already-issued session may remain active until it expires. For questions or requests about data handled by the Activity operator, contact ibra2008.tawalbeh@outlook.com.

8. Policy updates

This policy may be revised to reflect changes in the Activity's code, hosting, or data practices. The revision date at the top indicates the latest published version.
